# 문서 목차

처음 사용하는 분은 1 → 2 → 3 순서로 읽으면 됩니다. 인프라 담당자는 실행 매뉴얼과 GKE 문서를 먼저 보셔도 됩니다.

| 순서 | 문서 | 다루는 질문 |
|---|---|---|
| 1 | [빠른 실행](QUICKSTART_KO.md) | 설치가 됐는지 어떻게 확인하고, 첫 실험은 어떤 명령으로 하나요? |
| 2 | [상세 기술 문서](TECHNICAL_GUIDE_KO.md) | 같은 모델인데 왜 값이 다르고, 어디를 어떻게 비교하나요? |
| 3 | [실행 매뉴얼](RUNBOOK_KO.md) | 모든 명령, 결과 회수, 동일 입력 replay, FP64 비교를 어떻게 하나요? |
| 4 | [GKE 구성](GKE_KO.md) | H200·Ironwood 노드풀에서 실험 Pod를 어떻게 실행하나요? |
| 5 | [개발 안내](DEVELOPMENT_KO.md) | 설치 구조, 코드 수정, 테스트, wheel, CI는 어떻게 관리하나요? |
| 6 | [Git 등록](GIT_GUIDE_KO.md) | 처음 Git에 올리고 새 변경을 배포하는 순서는 무엇인가요? |
| 7 | [vLLM 비교](VLLM_KO.md) | 기존 서빙 환경의 출력과 레이어 계산을 어떻게 비교하나요? |
| 8 | [검증 기록](VALIDATION_KO.md) | 무엇을 실제로 검사했으며, 아직 확인하지 않은 것은 무엇인가요? |

## 파일을 읽을 때 구분할 것

- **소스:** `src/parity/`의 실제 실행 코드입니다.
- **과거 검증 증거:** `validation_evidence/`의 `v1_1`, `v1_2` 파일을 제외한 기존 JSON과 CPU 예시 보고서는 v1.0의 기록입니다. 현재 버전의 검사는 검증 기록의 v1.2 절을 봅니다.
- **생성 데이터:** `runs/`, `reports/`, `data/`는 사용자가 실행하면서 생성합니다. 저장소에 포함하지 않습니다.
- **배포 템플릿:** `deploy/*.yaml`에는 사용자의 실제 노드풀 이름을 넣어야 합니다.

현재 버전은 임의의 모든 LLM을 자동 지원하는 도구가 아닙니다. 지원 범위는 [저장소 README](../README.md)에 명시합니다.
